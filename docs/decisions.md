| ADR-012 | 2026-09-15 | **Movement = data-driven `MovementDef` + one `IMovementResolver` per geometry, in a string-keyed registry** | Walk / jump / teleport differ in *geometry* (path search, straight-line clearance, point pick); everything else (terrain enterability and cost, occupancy, height flags) is a per-ability data table read through `MovementContext`, so new kinds are one class + one JSON file and variants like "fly" are data only. `Enumerate` and `Validate` on the same object serve UI highlight, server validation and bots, so they cannot drift. `MovePlan` separates `Path` (animate) from `EnteredTiles` (tile effects), so hazards/traps hook in later without touching resolvers. Unknown modes fail closed. | Fixed `enum MovementType` + `switch` (old prototype: every new kind touched five files); strategy-per-*trait* (explodes combinatorially, Wesnoth avoids it with cost tables); physics volumes for tile effects |
| ADR-013 | 2026-09-15 | **Integer-exact hex lines (`HexLine`) for every rule; `Hex.Line` (doubles) is presentation-only** | Jump clearance and line of sight must match bit-for-bit on server and WebGL client. `HexLine` samples the exact rational point `(a·(N−i)+b·i)/N`, detects edge/corner hits exactly and returns all grazed hexes (supercover), so a grazing arc is blocked by *either* flanking tile and `Line(a,b)` always agrees with `Line(b,a)`. | Epsilon-nudged float line (asymmetric, platform-sensitive); Bresenham in offset coords (works, but needs a coordinate conversion and does not surface ties) |
| ADR-014 | 2026-09-15 | **One immutable `ContentCatalog` per process, two-phase (parse then link), fail-closed, sorted tables, content hash** | Every peer (Unity client, ASP.NET server, xunit) feeds the same `(path, text)` pairs into the same loader, so parity is by construction and verified by a SHA-256 over canonical JSON. Collecting all errors with file names makes a data folder fixable in one pass. Sorted-by-id tables give stable wire indices without hashing ids (RimWorld's short-hash collisions). Unknown files are errors so misplaced content cannot silently vanish. No inheritance/patching in data until real duplication appears (every engine that has it grew ordering rules). | Resources.LoadAll (no subfolder info, discouraged); Addressables/StreamingAssets on Web (extra requests, no sync load, patching we forbid anyway); hand-maintained TextAsset lists (drift); Def inheritance / macros (premature) |
| ADR-015 | 2026-09-15 | **Alternating turns with a per-turn cap; timeout = skip; explicit End Turn** | Resolves PIN-001. Chess-like alternation keeps hidden-information reveals legible (one actor at a time) and matches the chess-clock model already in `timecontrols.json` (`turnCapMs`). A turn that reaches its cap with no action taken is treated as a skip (the turn passes, nothing happens); an End Turn control lets a player pass early. Clock presentation follows Hearthstone rather than chess: no visible numbers, a rope that appears for the last seconds of a turn and burns down, and an idle penalty (a turn skipped with no action makes the next turn start with a short fuse that resets to full the moment the player acts), so idling costs more than thinking. HUD placement: turn owner + rope top-centre, End Turn bottom-right, action bar bottom-centre sectioned by ability `category` (movement / weapon / spell), examine panel left. Nothing is armed by default: the board only targets while an action is armed, and clicking a unit with nothing armed opens examine (opponent abilities show as unknown until first used). Local knobs (map, classes, turn seconds, rope, penalty) live in a `MatchSettings` asset until the real match setup exists. The action economy (move + action vs points) is still open; the HUD binds to an `IMatchHudSource` seam so that decision does not touch UI code. | Simultaneous planning + resolution (double-blind guesses undercut the reveal mechanic; harder to explain), initiative-based (adds a stat to balance before the core loop exists) |
| ADR-016 | 2026-09-15 | **Action-point economy: 3 AP per turn per unit (`stats.ap`), flat `cost` per ability use, unlimited reuse, no carry-over** | Chosen over move+action (too rigid for boons like double-move), single action (melee cannot close), and move+action+bonus (too much to balance before the loop exists). A flat cost per use keeps the movement resolvers untouched ("three steps" is three 1-AP walks) and lets a 1-AP jab and a 2-AP strike coexist. AP is the *only* per-turn limit, so a cheap attack repeated is a deliberate balance lever in data. Unspent AP is lost, so idling has no upside (fits the rope rule in ADR-015). AP lives on the unit, not the player, so summons can arrive later without a rewrite. | Action pools with carry-over (adds a banked pip and a stat to explain); `usesPerTurn` limits (extra rule; the AP cost already prices repeats) |
| ADR-017 | 2026-09-15 | **Deterministic damage as a fixed-order list of signed integers: `base + power.<type> − defense.<type> + Σ flat modifiers`, floored at 0; one calculator runs both the knowledge-limited preview and the full resolution** | Fire Emblem, Wildermyth, XCOM and Into the Breach all keep damage legible with flat subtractive defense and flat additive situational terms; percentages only survive where they are computed as integer basis points (Wesnoth). Stats are an open string-keyed table on classes, but keys follow `power.<type>` / `defense.<type>` for a damage type declared in `rules.json`, so the type both picks the stat pair and acts as a tag modifiers match. Modifiers (`modifiers/*.json`) are one trigger (`dealDamage` / `takeDamage`), a conjunction of conditions (`damageTypes`, `tags`, `heightAdvantage`) and one flat `effect.damage`; *who owns them* is the attachment (unit via boon, terrain, map hex `effect`, or `rules.globalModifiers`), never the definition. Height advantage is therefore just the global `high-ground` modifier. Hidden modifiers (`visibility: hidden`) are dropped from a player's preview (counted as "unknown") and revealed by an event the moment they change an actual result. Preview and actual are the same function with a different `Knowledge`, so they cannot drift. | Dice / hit chance (RNG undercuts the reveal mechanic and the lethal-maths readability the design wants); multiplicative buckets (need a combat log to understand); fixed C# stat set (every new stat touches Core); per-attack explicit stat keys (nothing for modifiers to hook on); enemy HP hidden (kill race unreadable) |
| ADR-018 | 2026-09-15 | **Rules core shape: `MatchState.Validate` (pure) / `Apply` (sole mutator, returns events) / `EnumerateLegal` (structural candidates filtered by `Validate`); timeouts are `EndTurnCommand(Timeout)` submitted by the server; `PlayerView` + `EventFilter` are the only things a client sees; all abilities and hidden modifiers are revealed per viewer on first use** | boardgame.io's fused move/validation is a documented pain (issue #292); OpenSpiel's legal-actions/apply split is what makes bots and UI trivial. One validation path means the HUD highlight, the server and the bot cannot disagree, and the bot is a five-line loop over `EnumerateLegal`. Recording a timeout as a command keeps replays `seed + command list` with no clock. Per-viewer revealed sets live in state, never in data, and reveal events precede the event that needed them so a client updates atomically. | Executing to find out legality; separate event types for hidden vs revealed uses (shape leaks); client-requested previews from the server (would leak hidden modifiers) |
| ADR-019 | 2026-09-15 | **HUD package "Hybrid" for hp / ap / attack preview / feedback** (research + four mocked options, Rohan picked D): thin segmented hp bar + number under every unit, faded until hovered or an action is armed; ap dots on the action bar, hovering an ability tints the dots it would spend red (Divinity OS2), each button shows its cost, unaffordable = desaturated; attack preview = ghosted hp delta on the target's bar + compact line-item tooltip anchored to the target with a "?" row when it has unrevealed modifiers; feedback = damage flyover, and when actual ≠ preview a second line names the revealed modifier whose icon then stays on the unit. | ADR-021 | 2026-09-16 | **Two damage lanes, `weapon` and `spell`, with `power.weapon` (Strength) / `power.spell` (Magic) and per-lane armour `defense.weapon` / `defense.spell`; elements (fire, frost, …) are a modifier class carried as an `element` tag on attacks, never a third lane** | Keeps the ADR-017 formula and the generic `power.<lane>` / `defense.<lane>` stat table; only the lane list changes (`melee/ranged/magic` → `weapon/spell`). | ADR-022 | 2026-09-16 | **Lineage grants a fixed starting Blessing and defines the between-round draft pool. | ADR-023 | 2026-09-16 | **Height-aware line of sight and trajectories.** Sight is a straight ray from the attacker's aim point to the target's, over integer heights in *body units* (`rules.heights`: 1 level = 3 units, hero body 6, aim 4). An intervening column blocks when its top *reaches* the ray — `top·b ≥ h0·(b−a) + h1·a` at a sample `a/b`, a graze blocks — and a column is the tile top plus any living body standing on it. Endpoints and holes never block; unwalkable terrain is solid. An attack declares two independent required fields, `lineOfSight` (must I see you) and `trajectory` (`direct` / `arc` / `sky`, one `ITrajectoryResolver` each in a string-keyed registry), and is legal only if both pass; `apex` is required iff `arc`, and an arc is an integer parabola peaking `max(h0,h1) + apex` sampled at both ends of every intervening tile. Range bands become Euclidean: `minRange² ≤ q²+qr+r² ≤ range²`. | Cover should depend on *where you stand*, not only on what is there, and the two fields let a bow drop an arrow behind a wall it cannot see past while a gun cannot. Keeping everything integer and cross-multiplied (no division, `long` intermediates) keeps server and WebGL client bit-identical, as ADR-013 does for hex lines. Sampling each tile at both of its edges is exact rather than approximate: a tile is a prism and a monotone flight is lowest at an edge. A circular band means a range circle drawn on the board is honest; hex distance would make the drawn circle lie from radius 7 up. Trajectory, apex, sight and the band are read through one seam (`AttackDef.WithTrajectory`), so an Enchant can swap a flight without touching a resolver. Design: `#line-of-sight`, `#trajectories`, `#attacks`. | BattleTech / ASL level buckets (cannot express distance-sensitive cover: a wall blocks the same from 1 tile as from 5); ASL blind-hex tables (the same maths hidden in a lookup table nobody can audit); "an arc ignores everything in between" (nothing left for an apex boon to change, and a wall would never matter to a bow); hex-distance bands drawn as circles (the circle lies); floating-point ballistics (drifts between IL2CPP and the server) |
| ADR-024 | 2026-09-16 | **Bodies and props.** One `IBody` interface unifies heroes and props for occupancy, sight and trajectory blocking, and targeting; `BodySet` (units in set order, then props in map authored order) is what movement and targeting receive. Anything with hit points can be hit and nothing else, so a destructible pillar is a target and an indestructible wall is only an obstacle. Props are neutral (`Owner == -1`), entirely public in `PlayerView`, placed by a map hex's `prop` field (symmetric, on walkable terrain, never on a spawn), and are removed when destroyed without ending the round. | The alternative shapes all leak: making targeting branch on "unit or prop" duplicates every rule, and making a prop a kind of terrain means it cannot be damaged and has no aim point to shoot at. A single interface means "anything with health can be hit" is one line rather than a type switch, and the first summon or shield generator is a new `IBody`, not a new rule. Props public keeps the damage preview honest, exactly as public gear does (ADR-022); hidden information stays on characters. Ids continuing after the units keep the wire a single integer space. Design: `#props`, `#attacks`. | Props as unwalkable terrain with a height (no health, no aim point, cannot be destroyed); a parallel `Obstacle` list with its own blocking rules (two code paths to keep in step); owned props / summons now (needs an owner, a spawn action and a reveal rule — premature) |
