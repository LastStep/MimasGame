### Guard notes (four false positives, none routed around)

`guard-bash.mjs` blocks a command when it *looks like a write* **and** mentions a protected path. Its
write-detector includes the regex `>>?\s*\S`, which matches things that are not writes:

- `2>&1` — so any read-only command with stderr redirection and a protected path in it is blocked.
- `>(` inside a C# generic, e.g. `FindFirstObjectByType<MatchSession>()` in a `unity command eval`.

Combined with path matching that does not know Unity-relative from repo-relative, this blocked:

1. a read-only `python -c` that *opened the design page to read it*;
2. `ls`/`find` over the package cache;
3. **`unity command get_scene_hierarchy --path Assets/_Game/Scenes/Arena.unity`** — the guard blocking
   the very path its own message recommends ("use the live Editor for Unity assets");
4. a `git commit` whose *message prose* mentioned `Lobby.unity` and `LoadoutPresets.asset`.

Each was handled by using a read-only tool, splitting the command, or `git commit -F`, and by declaring
the paths this task legitimately writes. Nothing was rephrased to slip a write past the guard. Two
suggestions for whoever owns it: treat `2>&1` and `>(` as not-writes, and match `allows_assets` against
both spellings of a Unity path.

Unity's `**/Temp/**`. Scripts for this session went to `C:\Users\droha\AppData\Local\mimas-scratch`
