### I drafted M2 from a stale picture of the repo

This session started at commit `12e13cb`. By the time I came to commit, `main` was at `2d5f606` — two
commits had landed **during** the session, from concurrent work in this repo:

- `15e3be0` — aiming specs verified, `slnx` fixed in CLAUDE.md, pipeline editor config ignored.
- `2d5f606` — **`docs/specs/2026-09-17-online-slice.md`, 757 lines**, plus ADR-026, ADR-027, ADR-028
  and a design page update.

That spec is a complete, code-checked M2 work order written the same day from a three-round question
round with Rohan, locking twelve decisions: the client mirror, the hand-written wire codec, a flat 30 s
server-authoritative turn with lag grace, guest tokens in `PlayerPrefs`, a 60 s reconnect grace then
forfeit, `ResignCommand`, a lobby scene, and a FIFO queue.

I had written five speculative one-pagers proposing room codes, a per-game chess clock, a two-minute
reconnect that ends in a draw, and rematch — and asking Rohan open questions that ADR-027 and ADR-028
had already answered. Committing them would have put five documents into his inbox that contradicted
decisions he had just made.

**Deleted.** Replaced by `F-online-slice.md`, which describes the approved spec in the plain language
the one-pager format is for, maps its done-when onto ledger entries, and says explicitly that where it
and the spec disagree, the spec wins. `F-deploy.md` survives, because the spec stops at local
end-to-end by design (D9) and deployment is genuinely still open.

**What I should have done:** checked `git log` against the repo state I had read, before writing
anything for Rohan to approve. The session-start protocol tells an agent to read `STATE.md` first — but
`STATE.md` did not exist yet in this repo, which is precisely the gap this task was closing. Once it
exists, an agent reading it would have found the spec named. This particular hole closes itself.
