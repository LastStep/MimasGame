# Plan: Finish M2 in the browser

Written for Rohan, who does not read code. The detailed work order is
`docs/specs/2026-09-21-m2-browser-finish.md`; this page is the shape of it.

## What this will do

After a match, both players land back in the same room with the same code and can play again by
pressing Ready. The page a friend opens is called Mimas, fills the window, has no Unity splash or
footer, and loads behind a thin bar with a percentage. The room gets a Copy code button. A refused
shot tints the tile that blocked it, and pillars are drawn the size of the hex they really block. The
server only accepts game connections from the real site, and the smoke test can run in three browser
engines.

## Approach

1. **The server stops closing the room when a match ends.** It goes back to "waiting", un-readies
   both seats, frees a seat whose player is gone, and starts a fresh match when both press Ready. A
   round number appears in the logs. Six new server tests, including two full matches in a row over
   real sockets.
2. **A reload after a match lands you back in your room**, not in front of a dead "Play vs bot".
3. **The server checks where a connection comes from.** On the live box only the real site may open
   the game socket. Locally nothing changes. Three tests.
4. **The client keeps the room across the result screen.** The banner button says "Back to room";
   the lobby opens on the room panel with the result on its status line.
5. **Copy code** beside Copy link, checked by reading the real clipboard back.
6. **The blocked shot**: two documented cases from the map first, then the tile tint and the
   hex-sized pillars.
7. **The Mimas page**: Unity's default template copied and rewritten; splash off; product renamed.
8. **The smoke test learns WebKit and Firefox.**
9. **Docs and the design page** record all of it; two short decision records.
10. **You deploy** with the usual one command, play a bot match, rematch, then a friend by code. A
    short session afterwards measures the live site again and hands to a verifier.

## What could go wrong

The Unity splash setting might turn out to be licence-gated after all (the spec says what to do);
Firefox or WebKit may not launch headless on Windows (same); driving a whole rematch in a headless
browser may take longer than it is worth (the Editor proof and the server tests carry it).
